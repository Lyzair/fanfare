# Release 1.0.0: packages and images for Fanfare and Fanfare Studio

## Intent

Publish version 1.0.0 of both projects so a club can download Fanfare (and optionally Fanfare
Studio) and run it on its own computer, with the manuals included. Every later release follows
the same path: push a tag, get a GitHub release with downloads and a container image.

## Goals

- One release workflow per repo, started by pushing a tag `v<version>` (e.g. `v1.0.0`).
- The workflow runs the tests, builds the packages and images, and creates the GitHub release with
  the packages attached as `.zip` and `.tar.gz`, plus a `SHA256SUMS` file.
- Fanfare packages, each with the app, the start files, `README-local.txt`, the manual and the licences:
  - `fanfare-1.0.0-all`: every voice (about 700 MB).
  - `fanfare-1.0.0-<lang>`: one voice, one package for each of the 10 languages (about 130 MB each).
  - `fanfare-1.0.0-none`: no voices (about 70 MB), so updating means unpacking it over the old folder.
- One Fanfare Studio package, `fanfare-studio-1.0.0`: only what's needed to run it, plus start files and a
  beginner manual in English and German.
- Images on GitHub's container registry (ghcr.io), tagged `1.0.0`, `1.0`, `1` and `latest`:
  - `ghcr.io/lyzair/fanfare`: linux/amd64, linux/arm64, linux/arm/v7 (the existing Dockerfile).
  - `ghcr.io/lyzair/fanfare-studio`: the CPU version only, linux/amd64 and linux/arm64.
- Both projects go to version 1.0.0 (`package.json`, `pyproject.toml`).

## Non-goals

- No Docker Hub.
- No published ROCm or CUDA images. The Studio README and manual explain how to build them
  (`compose.rocm.yaml`, `compose.cuda.yaml`).
- No installers, signed binaries or auto-update.

## Anti-goals

- A package that contacts any server while Fanfare runs. Voices are never downloaded at runtime.
- A package that starts but breaks when a voice is missing.
- Shipping development tooling (tests, evaluation and tuning scripts) in the downloads.

## Approaches considered

- **Registry:** ghcr.io (chosen: free, no extra account or secret, images listed on the repo
  page), Docker Hub (needs an account and a token secret, rate limits on anonymous pulls), or
  both (combines the costs of both).
- **Fanfare package size:** all voices in one package; one package per language; app only. The
  user chose all three: one with every voice, one per language, and one with no voices for updates.

## Design

### Fanfare: one build, packages differ only in `voices/`

`scripts/package-local.mjs` gains a voice selection (`all`, `none`, or a language code) and
writes both formats (`.zip` and `.tar.gz`). Every package holds the same app files, so `none`
is a drop-in update for any of them.

**My call:** the app checks at startup which voices are present (a same-origin request for
each voice's `.onnx.json`, which is small). A voice that isn't there shows in the selector as
"not included in this download" and can't be picked. A short hint says how to add it: download
that language's package, or the `all` package, and copy its `voices/<lang>` folder in. The
GitHub Pages demo includes every voice, so it doesn't change. When the voice of the chosen
language is missing, the app doesn't fail: it shows the same hint where it would otherwise start
preparing voices.

`README-local.txt` gets a section on updating (unpack `none` over the old folder; your
`voices/` stays) and adding voices. `voices/LICENSES.md` and the licence notices are in every
package.

### Fanfare Studio package

**My call:** contents are `src/`, `pyproject.toml`, `uv.lock`, `README.md` (the build needs it),
`LICENSE`, `voices.toml`, `voices/`, `docs/model-choice.md` (licences and sources), the manual and
start files. Tests, `scripts/`, `eval.toml`, Docker files and `samples/` stay out. A smoke test
unpacks the archive in CI and starts it with the `mock` backend to show nothing is missing.

Start files `start-studio.sh`, `start-studio.command`, `start-studio.bat`:
1. If `uv` is missing, explain how to install it (link to the official installer) and stop.
2. Otherwise run `uv run --frozen --extra onnx --extra cpu fanfare-studio` (on macOS,
   `--extra cpu` resolves to plain PyPI torch, as `pyproject.toml` already says).
3. Mention that the first start downloads about 1.6 GB of model files from Hugging Face.

**My call:** the manual goes in `docs/manual/en.md` and `docs/manual/de.md`, written for
beginners: what Studio is, install `uv`, start it, connect Fanfare (allowing the origin, e.g.
`fanfare-studio allow https://lyzair.github.io`), adding the club's own voice with consent,
stopping and uninstalling, Docker (`docker run` with ghcr), and building the ROCm and CUDA
versions yourself. Markdown that also reads well as plain text.

### Workflows

- `fanfare/.github/workflows/release.yml` (on `push: tags: ['v*']`): check that the tag
  matches `package.json`, test, build, `check:dist`, package all 12 variants in both formats,
  write `SHA256SUMS`, create the release (`gh release create`, generated notes plus a table
  of the downloads). A second job builds and pushes the image (buildx, QEMU, `docker/metadata-action`
  for the tags, `packages: write` only in that job).
- `fanfare-studio/.github/workflows/release.yml`: the same shape: tag check against
  `pyproject.toml`, `uv run pytest` (the watermark test needs the CPU torch extra in CI),
  package, smoke start, release, image (CPU build arg, amd64 + arm64).
- Permissions: `contents: write` only for the release job, `packages: write` only for the image
  job; build and test jobs stay read-only (as in `pages.yml`).
- The existing CI keeps running on pushes to `main`.

### Docs

- Fanfare `README.md` and `docs/self-hosting*.md`: "Download" section (which package to
  pick) and `docker run ghcr.io/lyzair/fanfare:1`, with build-it-yourself kept as the alternative.
- Studio `README.md`: download section, ghcr image, "Build ROCm / CUDA yourself".

## User steps (can't be automated)

- After the first image push, set each package on ghcr.io to **public** (GitHub creates them
  private; the change is in the package's settings on github.com).
