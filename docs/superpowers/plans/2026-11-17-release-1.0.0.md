# Release 1.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A tag push `v1.0.0` in each repo builds tested `.zip`/`.tar.gz` packages and a ghcr.io image and publishes a GitHub release.

**Architecture:** Fanfare: one build; `scripts/package-local.mjs` writes 12 variants (all, none, 10 languages) that differ only in `voices/`; the app detects missing voices at runtime. Studio: a stdlib Python packager plus start files and a new beginner manual. Each repo gets `.github/workflows/release.yml` (tests → packages → `gh release create`; separate image job).

**Tech Stack:** Node 24 ESM + fflate + `node:zlib`, Preact/TypeScript, Vitest; Python 3.12 + uv + pytest; GitHub Actions, buildx/QEMU, ghcr.io.

**Spec:** `docs/superpowers/specs/2026-11-17-release-1.0.0-design.md` (fanfare repo; covers both repos)

Repos: `F` = `/home/rene/Projects/fanfare`, `S` = `/home/rene/Projects/fanfare-studio`. Commit in the repo the task names. Do not push and do not create tags (the user does that).

## Global Constraints

- Version `1.0.0` in `F/package.json` and `S/pyproject.toml`; the release workflow fails if tag `v<x>` ≠ that version.
- Package names: `fanfare-<ver>-<variant>.{zip,tar.gz}` with variant ∈ `all`, `none`, `ar de en es fr it nl pl tr uk`; `fanfare-studio-<ver>.{zip,tar.gz}`; plus `SHA256SUMS` per release.
- Top folder inside every Fanfare archive is `fanfare/` (no version), so `none` unpacks over an older folder. Studio: `fanfare-studio/`.
- Images: `ghcr.io/lyzair/fanfare` (linux/amd64, linux/arm64, linux/arm/v7), `ghcr.io/lyzair/fanfare-studio` (CPU build, linux/amd64, linux/arm64); tags `1.0.0`, `1.0`, `1`, `latest`.
- No runtime requests to other origins (Fanfare CSP and `check:dist` stay as they are). Voices are never downloaded at runtime.
- Workflow permissions: read-only by default; `contents: write` only in the release job, `packages: write` only in the image job. Actions at the majors used in `F/.github/workflows/pages.yml` (checkout v7, setup-node v7, setup-python v7, upload-artifact v7, buildx/qemu v4) plus `docker/login-action`, `docker/metadata-action`, `docker/build-push-action` at their latest majors (look them up with `gh api repos/<a>/releases/latest`).
- Executable bit on `*.sh`, `*.command`, `fanfare-local.py` survives both archive formats.
- All user-visible app strings exist in all 10 language packs (`F/src/i18n/*.ts`; `en.ts` defines the keys).

## Review Focus

1. Unpacking `fanfare-…-none` over a folder from the `de` package keeps `voices/de` and the German voice still works: covered by the overlay test in Task 2.
2. A user opens the `de` package and switches the UI to English: the voice shows as not included and "Prepare voices" explains instead of failing with an engine error: Task 1 tests.
3. `voices/LICENSES.md` and `licenses/*` are in every variant, including `none`: Task 2 test.
4. The Studio archive started from a different working directory still finds `voices.toml`: start files `cd` to their own folder; Task 4 smoke test runs from outside the folder.
5. A tag that does not match the version (e.g. `v1.0` or `v1.0.1` with 1.0.0 in files) stops before anything is published: Tasks 3 and 6 use a tested `check-tag` step.
